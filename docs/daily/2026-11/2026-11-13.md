## 学了什么（用自己的话）

### 音频基础

- 采样/量化/编码：采样就是对模拟信号按照一定的时间间隔进行离散取值，量化就是把连续幅度离散到有限等级，编码：去除无关性、去除冗余，心理声学是编码的理论基础，人耳听觉频率范围20Hz~20KHz
- PCM 码率公式：采样率x位深x通道数(未压缩原始码率)，例如48KHz 16bit 双通道，码率公式=48000 x 16 x 2 = 1.536Mbps， 一小时约 691MB，Opus 压缩后语音通常16～64kbps

- 心理声学（掩蔽/临界频带）：为什么有损压缩听不出来，一是听觉阈值，不同频率的声音可听下限不同，阈值以下的声音可以丢掉；二是：频域掩蔽，强音会掩盖邻近频率的弱音，且不对称，低频掩蔽高频强于反向（向上掩蔽），三是：时域上的掩蔽，强音之前 前掩蔽（5～20ms）和之后 后掩蔽（50～200ms）的弱音会被掩盖，四是：临界频带， 人耳对频率的分辨不是线性的，编码器按照临界频带分配比特，掩蔽主要发生在同一临界带内（约24个Bark带）
- AAC 与 Opus 的取舍：Opus 码率范围 6–510 kbps，帧长 2.5–60ms（CELT 2.5–20ms，SILK 10–60ms），默认算法延迟 26.5ms（20ms 帧 + 6.5ms lookahead），最低 5ms；编码器内部固定 48kHz，与 RTP 时钟一致，输入支持 8/12/16/24/48kHz；支持带内 FEC（SILK LBRR，嵌前一帧低码率副本）、DTX（静音不发，只发舒适噪声参数）、PLC（丢包时用前一帧外推）。适合 WebRTC/实时通话。AAC 兼容性好，但 AAC-LC 延迟约 42.7ms，标准无带内 FEC/DTX，主要用于点播/直播/MP4。

### 视频基础

- YUV 与 4:2:0：YUV，Y亮度，UV是色度，人眼对色度不敏感，所以色度可以降采样 减少数据量
- I/IDR/P/B：I帧是关键帧，可以独立解码显示，IDR帧收到会立刻刷新解码，清空解码缓存，是一个GOP的开始，P帧是前向参考帧，解码需要参考前面的帧，B帧是双向参考帧，解码需要参考前面的帧也需要参考后边的帧，所以B帧的延迟比较大， 它要等收到后续参考帧后进行帧序重排才能解码，一般在RTC中不使用B帧，open gop 是该GOP中的B帧可以参考上一个GOP中的帧进行解码,压缩率高，但随机接入不干净，closed gop 是按照IDR帧为起点，不跨GOP参考，可以任意IDR帧开始解码，直播/RTC都用closed gop
- GOP 与 SPS/PPS：GOP是一组编解码帧组，两个IDR帧中间是一个GOP，SPS存profile/level/分辨率/帧率， PPS是存熵编码模式，QP，Slice分组
- H.265/AV1 的改进：H.265 用 CTU（16/32/64，最大 64×64）替代 H.264 的 16×16 宏块；同画质下码率比 H.264 低约 40–50%。AV1 超块最大 128×128，同画质码率比 H.264 低约 30–50%。H.264 帧内预测：4×4/8×8 各 9 种，16×16 为 4 种；H.265 为 35 种（33 角度 + DC + Planar）。
- H264宏块划分：完整的宏块大小是16x16(亮度)，划分方式（16x16,16x8,8x16,8x8）为了做运动估计和运动补偿，(8x8)子宏块还可以在划分（8x8,4x8,8x4,4x4）
- H265 CTU划分：CTU（coding tree unit 编码树单元）其标准范围是16x16, 32x32，64x64像素（针对亮度分量）,内部结构，一个CTU还可以通过四叉树结构，进一步划分为更小的编码单元（coding unit），CU的尺寸 从8x8 到64x64,这种灵活的分块方式是HEVC相比H264能大幅提升压缩率的关键 HEVC（High Efficiency Video Coding）

### 封装与时间戳

- MP4/TS/FLV 的差异：MP4 ftyp +moov+mdat, TS 是188字节定长包+PCR，抗丢包，冗余多，多用于直播广电， FLV tag(音频/视频/脚本) + 32位毫秒时间戳，RTMP载体，简单 延迟低
- PTS 与 DTS：PTS是显示时间，DTS是解码时间，在没有B帧的场景下这两个时间相同，但在有B帧的情况下PTS不等于DTS，因为B帧双向参考，需要在收到后向参考帧后才能解码
- 音画同步：有几个常见的同步策略，一是音频时间为准，视频向音频同步，二是外部时钟为准，音视频都向外部时钟同步，三是视频为准，音频向视频同步，常见使用时音频时间为准，视频向音频同步，超过同步阈值之后对视频做快放或者是丢帧操作

## 习题与答案

### A. 概念题（8 题）
1、为什么音频采样率要大于信号最高频率的2倍？
奈奎斯特定律：对一个最高频率为fmax的信号，若要以采样率fs采样并能无失真地重建原信号，必须满足 fs > 2 x fmax，如果不满足会出现信号的混叠
2、16bit量化的理论动态范围是多少，怎么估的？
96db的动态范围，按照（6db/bit的经验值）估算的
3、4:2:0相比4:4:4 省了多少数据？为什么可以省？
省了50%的数据，因为人眼对亮度比较敏感，对色度敏感度低， 2x2共享一组UV看不出差别
4:4:4 每像素是3字节，4:2:0 每像素是1.5字节
4、I帧，IDR帧有什么区别？
I帧是帧内编码，可以直接无参考帧解码渲染，IDR帧是可以刷新解码队列，清空参考帧队列，是GOP的开始，I帧不一定是IDR帧，但IDR帧一定是I帧
5、为什么B帧会增加延迟？
B帧是双向参考，既参考前向的帧还需要参考后向的帧，因此在B帧解码的时候需要等到后续帧收到后才能进行解码，因此需要考虑后续帧接收的网络延迟+解码延迟，显示时候需要重拍缓冲，B帧就会增加延迟
6、PTS和DTS什么时候不相等？
当有B帧的时候PTS和DTS不相等，没有B帧的时候PTS=DTS
7、H264的SPS和PPS分别存什么？
SPS：存profile,level,分辨率，帧率等信息
PPS：存熵编码模式，QP，slice组等
8、为什么视频编码常用YUV和不是RGB？
压缩效率，YUV把亮度和色度分离，可利用人眼特性对色度进行降采样（4:2:0），RGB三个通道同样重要，不好直接降

### B. 计算题（6 题）
1、48khz/16bit/立体声PCM，码率是多少，1小时占多少存储？
48000x16x2 = 1.536Mbps 1.536M x 3600 / 8= 691.2MB 
2、1080p、4:2:0、8 bit，一帧原始数据多大？30fps 下带宽多少？
1920x1080x1.5(Byte/像素) x 8 = 24.883Mb, 24.883x30 = 746.496Mbps
3、4 Mbps 的直播，1 小时消耗多少流量（GB）？
4Mbps x 3600 / 8bit / 1000 = 1.8GB
4、30fps 视频，GOP=60，多久一个关键帧？RTP 时间戳每帧步进多少？
2秒一个关键帧，GOP = 帧率 x I帧间隔， RTP时间戳每帧步进 = 90000/30 = 3000
每帧帧间隔 = 1000ms / 30 =33.3ms
5、128 kbps AAC，1 小时音频多少 MB？
128 x 3600 / 8 / 1000 = 57.6MB
6、4:2:2 相比 4:2:0，数据量增加多少百分比？
4:2:2 是2字节/像素，4:2:0是1.5字节/像素 （2-1.5）/1.5 = 33.3%

### C. 编码/封装题（6 题）
1、Baseline、Main、High profile的主要差异？
Baseline 是没有B帧，只支持I帧和P帧，使用CAVLC（基于上下文的自适应可变长度编码 Context- based Adaptive Variable Length Coding），无加权预测，低延迟，低复杂度
Main相比于Base line，支持B帧，熵编码加CABAC（基于上下文的自适应二进制算术编码Context- Based Adaptive Binary Arithmetic Coding），支持加权预测
High profile 在上边的基础上支持8x8变换，量化矩阵，同Main Profile相比在相同画质下码率更低
2、为什么直播常用TS而不是MP4？
TS的封装格式是188字节定长包+媒体负载，分片可独立播放，每片单独携带PAT/PMT可随时接入，抗丢包定长包+同步字，丢包能重新对齐，HLS/CDN生态成熟
MP4封装是ftyp + moov + mdat的方式，解码信息都在moov中存储，一般moov都在文件末尾，如果要解码需要把整个文件下载完成才可以，直播也可以使用fmp4,但兼容性不太好
3、FLV的时间戳单位是什么？有什么回绕问题？
FLV的时间戳单位是ms，封装时是32位的时间戳，在达到32位最大表示数字之后会产生时间回绕问题，周期是约49.7天
4、H265比H264省在哪？
H265采用CTU划分最大支持64x64, H264采用宏块方式划分，宏块大小是16x16,且H265的帧内预测方式支持35种，2种非角度模式，33种角度预测，更精细， H264的预测方式只有在4x4/8x8的时候支持9种预测方式，综合看H265在保持相同画质的情况下能达到更高的压缩比，相同画质下码率能降低40%～50%
5、什么是CRF？和固定码率有什么区别？
CRF是恒定质量模式（constant rate factor），编码器按照画面复杂度自动调节码率；固定码率（CBR）是保证带宽稳定，但画质存在波动，点播常用CRF，直播常用CBR/ABR
CBR（constant bitrate）：静态码率
ABR（average bitrate）：平均码率
VBR（variable bitrate）：动态码率
AVBR（adaptive variable bitrate）：自适应动态码率

6、关键帧间隔（GOP）设置长短各有什么利弊？
短GOP的话I帧间隔更小，I帧更频繁，在丢包能情况下 有新的I帧出现能减少丢包导致的参考帧丢失最终导致解码花屏等问题，但不好的是I帧过多导致码率变大，因为I帧的数据量比P/B帧大很多，需要更多的带宽承载
长GOP的话会有效降低I帧带来的码率增大，减少数据Burst，但过大的GOP会导致中间出现丢包/丢帧的时候解码无参考帧，导致解码花屏 恢复时间变长，此时需要FIR/PLI机制来强制生成I帧
直播常用1～2秒一个I帧

### D. 工程判断题（5 题）
1、用户反馈画面偏灰，可能是什么问题？
limited/full range搞错了（16～235/0～255），YUV和RGB转换矩阵用错（601/709），或者色彩空间标记丢失
2、直播卡顿，码率上不去，你会先查什么？
首先会排查编码参数配置，分辨率是多少，码率是多少，I帧是多少，编码格式是什么，采用的什么码控模式，摸清楚实际编码的输出是什么情况，然后会排查当前的网络带宽是否能支撑对应的输出码率，查上行丢包/RTT，编码器是否被限码，GOP，服务端
先看上行带宽/丢包/RTT（推流端），在看编码器是否被限码率，GOP是否过长，关键帧是否卡住，最后看服务端转发
3、音画不同步可能有哪些原因？
网络原因导致的丢包 导致音画不同步；音画同步的时间戳基线不一致，音频重采样导致的漂移，播放端缓冲策略问题，B帧重排，RTCP SR对齐错误；
4、为什么弱网下优先降码率而不是降分辨率？
降码率是渐进降质，用户还能看，降分辨率是突变，观感差且可能会涉及到重新协商，编码器内部会先降QP/帧率，再考虑分辨率

5、摄像头采集25fps,编码30fps会发生什么？
会出现帧率不均匀，采集25帧，编码30帧，编码器会重复帧或者插入空帧，导致时间戳抖动，卡顿感，应该采集和编码帧率一致，或者做帧率转换

FLV：tag（音频/视频/脚本）+32位毫秒时间戳
