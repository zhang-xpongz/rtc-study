## 学了什么（用自己的话，不抄资料）

### FrameBuffer 的定位

- 它是一个**线程不安全的数据结构**，不是调度器：只负责存帧、排序、判定，不决定什么时候解码。
- 排序用 **Frame ID**，分组用 **RTP timestamp**（temporal unit）。
- `frames_` 是 `std::map<int64_t, FrameInfo>`，插入即按 ID 有序，因此依赖图天然是单向的。
- 两个核心判定：
  - **continuous**：单帧的所有参考要么已解码，要么在缓冲里且连续。
  - **decodable unit**：整个 temporal unit 的参考都已解码或在 unit 内。

### InsertFrame 的 8 步

1. 清空 `new_continuous_temporal_units_`
2. `ValidReferences`：参考必须更早、不能重复
3. 旧帧判断：ID ≤ 最后解码 ID 丢弃；关键帧时间戳更新则 `Clear()`
4. 缓冲满：关键帧 `Clear()` 后插入，非关键帧丢弃
5. `map::emplace`，重复 ID 失败
6. `PropagateContinuity`：标记连续、更新 `last_continuous_*`
7. `FindNextAndLastDecodableTemporalUnit`：按时间戳分组，找第一个可解码 unit
8. 返回 `true/false`

关键理解：**关键帧能清空满缓冲**，因为它不参考任何帧，是新的依赖根。

### Frame ID 与 Temporal Unit（H.264）

- H.264 的 RTP 头里没有 picture ID，`RtpSeqNumOnlyRefFinder` 用**最后一个 RTP 包的 sequence number** 作为 Frame ID，并展开 16 位回绕。
- delta 帧的 `references[0]` = 上一个帧的最后一个 seq；IDR 的 `num_references = 0`。
- Temporal Unit 按 **RTP timestamp** 分组；H.264 用 **marker** 标记帧结束，`is_last_spatial_layer = markerBit`。
- 所以单层 H.264 下：**一帧 = 一个 temporal unit**，Frame ID 和 TU 基本 1:1。
- Frame ID 不是 `frame_num`、不是 POC、不是时间戳。

### 线程与生命周期

- `Call::CreateVideoReceiveStream` 在 **network 线程**；创建 `VideoReceiveStream2` 时把 `call->network_thread()` 传给 controller。
- `VideoStreamBufferController` 的 `worker_sequence_checker_` 只是**历史命名**，实际绑定的是传入的 network 队列。
- 因此 `FrameBuffer` 也在 **network 线程**被访问；它本身线程不安全，靠 controller 的 `RTC_DCHECK_RUN_ON` 串行化。
- 创建链：`Call::CreateVideoReceiveStream` → `new VideoReceiveStream2` → `CreateBuffer()` → `VideoStreamBufferController` → `FrameBuffer`。
- 销毁链：`Call::DestroyVideoReceiveStream` → `UnregisterFromTransport()` → `erase()` → `delete`。

### 单测（21 个）

- 测试脚手架：`FakeFrameBuilder().Time(ts).Id(id).Refs({...}).AsLast().Build()`。
- 相同 `Time` = 同一个 TU；**`AsLast()` 才关闭 unit**，不加就不完整（模拟 SVC 基层/增强层）。
- 核心用例：
  - `RejectInvalidRefs`：自引用/重复参考被拒
  - `LastContinuousFrameReordering`：乱序补齐后向前传播
  - `AdvanceNextDecodableOnExtraction`：提取后 `next` 前移
  - `AdvanceLastDecodableOnExtraction`：`last_rtp_timestamp` 可跳变
  - `KeyframeClearsFullBuffer`：满缓冲靠关键帧重置
  - `ReturnFullTemporalUnitKSVC`：一次返回整组多层帧

### 算法

- 56 合并区间：按左端点排序 + 一次扫描合并，O(n log n)

| 连续性/可解码扫描           | O(n)，n ≤ 800                        |
