    1. 音频基础¶

    1.1 从模拟到数字：采样、量化、编码¶

    声波（连续） → 采样（时间离散） → 量化（幅度离散） → 编码（压缩/打包）
    • 采样：按固定间隔取点。采样率必须 ≥ 2×最高频率（奈奎斯特），否则混叠。
    • 人耳可听 20 Hz–20 kHz → 44.1 kHz（CD）、48 kHz（音视频/通话）
    • 语音（300–3400 Hz）→ 8 kHz（G.711）
    • 量化：每个采样点的幅度用固定 bit 表示。
    • 16 bit → 96 dB 动态范围（6 dB/bit 经验值）
    • 8 bit 电话音质，24 bit 录音棚
    • 编码：PCM 是未压缩的；AAC/Opus 是有损压缩；FLAC 是无损压缩。

    1.2 PCM 与码率计算¶

    PCM 码率公式：

    码率(bit/s) = 采样率 × 位深 × 声道数

    例：48 kHz / 16 bit / 立体声

    48000 × 16 × 2 = 1,536,000 bit/s = 1.536 Mbps
1 小时 = 1.536e6 × 3600 / 8 ≈ 691 MB

    这就是为什么必须压缩：一路未压缩立体声就占 1.5 Mbps。

    1.3 心理声学：有损压缩为什么听不出来¶

    完整版（临界频带、掩蔽、SMR、预回声、AAC/Opus 实现）见 补充-心理声学.md。

    • 听觉阈值：不同频率的可听下限不同，阈值以下的声音可以丢掉。
    • 频域掩蔽：一个强音会掩盖邻近频率的弱音（临界频带内）。
    • 时域掩蔽：强音前后几十毫秒的弱音被掩盖。
    • 临界频带（Bark）：人耳对频率的分辨不是线性的，编码器按临界频带分配比特。

    编码器的核心是信掩比（SMR）：把每个频带的信号能量和掩蔽阈值比较，只保留高于阈值的成分。AAC 的 MDCT + 量化、Opus 的 CELT/SILK 混合，都是这个思路的不同实现。

    1.4 常见音频编码与选型¶

    Opus 为什么低延迟/自适应、AAC 为什么延迟高，见 补充-Opus与AAC对比.md。

    编码 典型码率 延迟 场景
    G.711 (PCMU/PCMA) 64 kbps 极低 电话、SIP
    AAC-LC 96–192 kbps 中（几十 ms） 直播、点播、MP4
    Opus 16–64 kbps 低（20 ms 帧） WebRTC、实时通话
    MP3 128–320 kbps 中 历史遗留
    FLAC 无损（约 50–60% PCM） 高 音乐归档

    WebRTC 默认 Opus：48 kHz 内部采样、20 ms 帧、支持 FEC/DTX、码率自适应好。 RTMP/FLV 常见 AAC：兼容性好，但延迟和抗弱网不如 Opus。

    1.5 音频工程里的坑¶

    • 采样率转换（SRC）：48k ↔ 44.1k 不是简单丢点，要重采样滤波，否则混叠。
    • 时钟漂移：采集端和播放端晶振不同，长时间会累积，表现为音频“越播越多/少”，需要 drift compensation。
    • 爆音/咔哒声：缓冲区边界没对齐、增益突变、丢包没做 PLC。
    • 单声道/立体声：WebRTC 里常见 mono → stereo 上混，要注意能量不要翻倍。

    2. 视频基础¶

    2.1 像素与色彩空间¶

    • RGB：屏幕显示用，三个通道等权。
    • YUV：亮度（Y）+ 色度（U/V）。人眼对亮度敏感、对色度不敏感，所以色度可以降采样。
    • 转换（BT.601）：
    Y = 0.299R + 0.587G + 0.114B
U = -0.169R - 0.331G + 0.500B + 128
V = 0.500R - 0.419G - 0.081B + 128
    • BT.601 / BT.709 / BT.2020：不同色域标准，SD 用 601，HD 用 709，HDR 用 2020。搞错会偏色。
    • Limited range（16–235）vs Full range（0–255）：视频编码常用 limited，PC 显示常用 full，转换错会“发灰”或“死黑”。

    2.2 色度采样与带宽¶

    格式 每像素字节（8 bit） 相对 4:4:4
    4:4:4 3 100%
    4:2:2 2 67%
    4:2:0 1.5 50%

    4:2:0 的含义：每 2×2 个像素共享一组 U/V，Y 保持全分辨率。

    1080p 一帧 4:2:0：

    1920 × 1080 × 1.5 = 3,110,400 字节 ≈ 2.97 MB
30 fps → 93.3 MB/s ≈ 746 Mbps（原始）

    2.3 帧率、分辨率、码率¶

    • 码率 ≈ 分辨率 × 帧率 × 每像素比特 × 压缩率倒数。
    • 运动越大、细节越多，同样画质需要越高码率。
    • 常见目标：1080p30 直播 4–8 Mbps；720p30 2–4 Mbps；4K 15–25 Mbps。
    • 降码率时优先降分辨率还是帧率取决于内容：体育/游戏优先保帧率，静态画面优先保分辨率。

    2.4 视频压缩原理¶

    帧内预测（空间冗余） + 帧间预测（时间冗余） + 变换 + 量化 + 熵编码
    • 帧内预测：用邻近像素预测当前块（H.264 有 9 种 4×4 模式）。
    • 帧间预测：运动估计 + 运动补偿，只编码残差。
    • 变换：DCT/整数变换，把能量集中到低频。
    • 量化：有损的主要来源，QP 越大画质越差、码率越低。
    • 熵编码：CABAC（H.264 Main/High）或 CAVLC（Baseline）。

    2.5 H.264 的关键结构¶

    概念 含义
    NAL Unit 网络抽象层单元，类型：1 非 IDR 片、5 IDR、6 SEI、7 SPS、8 PPS、9 AUD
    Slice 一帧可切成多个 slice，便于并行和抗丢包
    I 帧 帧内编码，可独立解码
    IDR 立即解码刷新，清空参考帧队列，GOP 的起点
    P 帧 前向参考
    B 帧 双向参考，需要重排，延迟高
    SPS/PPS 序列/图像参数集，分辨率、profile、level 等
    GOP 两个 IDR 之间的帧序列

    Profile：

    • Baseline（66）：无 B 帧、CAVLC，适合低延迟/弱设备
    • Main（77）：B 帧、CABAC
    • High（100）：8×8 变换、更多工具

    Level 4.0 大致对应 1080p30（MaxFS 8192 宏块、MaxMBPS 245760）。

    2.6 H.265 / AV1 的改进¶

    H.264 H.265 AV1
    块大小 16×16 宏块 64×64 CTU 128×128 超块
    预测 9 种帧内 35 种帧内 更多方向 + 帧内拷贝
    并行 slice tiles/WPP tiles
    码率收益 基准 约省 40–50% 约省 30–50%
    专利 有 有 免专利（但生态复杂）

    3. 封装与时间戳¶

    3.1 封装格式¶

    MP4/TS/FLV 的结构、索引、时间戳与工程取舍，见 补充-MP4-TS-FLV封装格式.md。

    格式 结构 特点
    MP4 ftyp + moov + mdat 点播友好，moov 前置才能秒开；fMP4 用 moof
    MPEG-TS 188 字节定长包 + PCR 直播/广电，抗丢包，冗余多
    FLV tag（音频/视频/脚本）+ 32 位毫秒时间戳 RTMP 载体，简单，延迟低
    RTP 包头 + 负载 实时传输，无容器

    3.2 PTS / DTS / 时间基¶

    • PTS：显示时间戳（什么时候显示）
    • DTS：解码时间戳（什么时候解码）
    • 有 B 帧时，解码顺序 ≠ 显示顺序，所以 DTS ≠ PTS；无 B 帧时通常相等。
    • timebase：时间单位。MP4 常见 1/90000 或 1/1000；RTP 视频固定 90 kHz，音频用采样率。

    换算：

    秒 = timestamp × timebase

    33 位 90 kHz 时间戳约 26.5 小时回绕；FLV 32 位毫秒约 49.7 天回绕。

    3.3 音画同步¶

    • 以音频为主时钟（audio master），视频追音频。
    • 视频帧的 PTS 与音频播放位置比较，超阈值就丢帧/等待。
    • RTP 场景用 RTCP SR 把 RTP 时间戳映射到 NTP 墙上时间，再对齐两路流。

    3.4 从 RTP 看时间戳¶

    • 视频 RTP 时间戳步进 = 90000 / 帧率（30fps → 3000）
    • 音频 RTP 时间戳步进 = 采样率 × 帧时长（48kHz × 20ms → 960）
    • 起始值是随机的，不能直接比较两路流，必须靠 RTCP SR 对齐。

    4. 常见参数速查¶

    场景 参数
    实时通话 Opus 48k / 20ms、VP8 或 H.264、720p30、1–2 Mbps
    直播 H.264 High、1080p30、4–8 Mbps、GOP 2s、AAC 128k
    低延迟直播 H.264 Baseline、720p30、GOP 1s、2–3 Mbps
    监控 H.265、1080p25、2–4 Mbps、GOP 2–4s
    短视频 H.264/H.265、1080p30、CRF 编码、AAC 128k

    6. 参考答案与解析¶

    A 组¶

    1. 奈奎斯特采样定理：采样后频谱会周期延拓，若采样率 < 2×最高频率，高频会折叠到低频（混叠），无法还原。所以 20 kHz 上限需要 ≥ 40 kHz，实际用 44.1/48 kHz 留余量。
    2. 96 dB。经验公式 6.02 × bit 数 ≈ 6 × 16 = 96 dB。24 bit ≈ 144 dB。
    3. 省 50%。4:4:4 每像素 3 字节，4:2:0 平均 1.5 字节。人眼对色度分辨率不敏感，2×2 共享一组 UV 看不出差别。
    4. I 帧只是帧内编码，仍可能参考之前的 SPS/PPS；IDR 会清空参考帧队列，后续帧绝不参考 IDR 之前的帧，是随机接入点。GOP 从 IDR 开始。
    5. B 帧需要后向参考，编码器必须等后面的帧到达才能编码当前帧，解码端也要重排，因此增加端到端延迟。实时场景通常禁用 B 帧（如 -tune zerolatency）。
    6. 有 B 帧时。解码顺序是 I P B B，显示顺序是 I B B P，DTS 按解码顺序递增，PTS 按显示顺序。
    7. SPS：profile、level、分辨率、帧率、色度格式等序列级参数；PPS：熵编码模式、QP、slice 分组等图像级参数。
    8. 压缩效率。YUV 把亮度与色度分离，可利用人眼特性对色度降采样（4:2:0），RGB 三通道同等重要，不好直接降。

    B 组¶

    1. 48000 × 16 × 2 = 1,536,000 bit/s = 1.536 Mbps；1 小时 1.536e6 × 3600 / 8 = 691,200,000 B ≈ 691 MB。
    2. 1920 × 1080 × 1.5 = 3,110,400 B ≈ 2.97 MB/帧；30fps → 93.3 MB/s ≈ 746 Mbps。
    3. 4e6 × 3600 / 8 = 1.8e9 B = 1.8 GB（十进制；约 1.68 GiB）。
    4. GOP 60 帧 ÷ 30fps = 2 秒一个关键帧；RTP 步进 90000 / 30 = 3000。
    5. 128000 × 3600 / 8 = 57,600,000 B ≈ 57.6 MB。
    6. 4:2:2 是 2 字节/像素，4:2:0 是 1.5，增加 (2-1.5)/1.5 = 33.3%。

    C 组¶

    1. Baseline 无 B 帧、CAVLC、低延迟；Main 加 B 帧、CABAC；High 加 8×8 变换、更多工具，同画质码率更低。
    2. TS 是流式封装，188 字节定长包、带 PCR，丢包可恢复、可随时接入；MP4 的 moov 是索引结构，更适合文件点播，直播用 fMP4 也可以但兼容性不如 TS。
    3. 毫秒（32 位无符号）。约 49.7 天回绕；长时间推流要做时间戳回绕处理。
    4. 更大的 CTU（64×64）、更多帧内预测模式（35 种）、更好的运动预测、SAO 滤波、tiles/WPP 并行，整体比 H.264 省 40–50% 码率。
    5. CRF 是恒定质量模式，编码器按画面复杂度自动调码率；固定码率（CBR）保证带宽稳定但画质波动。点播常用 CRF，直播常用 CBR/ABR。
    6. GOP 短：随机接入快、抗丢包好、但 I 帧多导致码率上升；GOP 长：码率省，但首帧慢、丢包后恢复慢。直播常用 1–2 秒。

    D 组¶

    1. 常见原因：limited/full range 搞错（16–235 vs 0–255）、YUV↔RGB 矩阵用错（601/709）、或者色彩空间标记丢失。
    2. 先看上行带宽/丢包（推流端），再看编码器是否被限码率、GOP 是否过长、关键帧是否卡住，最后看服务端转发。
    3. 原因可能有：时间戳基准不一致、音频重采样导致漂移、播放端缓冲策略不同、B 帧重排、RTCP SR 对齐错误。
    4. 降码率是渐进降质，用户还能看；直接降分辨率是突变，观感差且可能触发重新协商。编码器内部会先降 QP/帧率，再考虑分辨率。
    5. 会出现帧率不均匀：采集 25fps 而编码 30fps，编码器会重复帧或插入空帧，导致时间戳抖动、卡顿感，应该让采集与编码帧率一致或做帧率转换。
