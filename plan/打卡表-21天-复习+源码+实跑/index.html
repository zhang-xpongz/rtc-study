    21 天打卡表：复习 + 源码走读 + 实跑¶

    适用：每天 8–10 小时可投入 周期：2026-11-13 → 2026-12-03（21 天） 三条线并行：专题复习 3h ｜ 源码走读 2.5h ｜ 实跑实验 2h ｜ 算法 1h ｜ 输出 0.5h

    0. 每日时间块（9 小时版）¶

    时段 内容 说明
    08:30–11:30 专题复习（3h） 按《复习资料包》M1–M16
    13:30–16:00 源码走读（2.5h） 按《WebRTC源码走读地图》
    16:15–18:15 实跑实验（2h） 抓包/日志/部署，对照源码
    20:00–21:00 算法（1h） 2 道中等题，限时
    21:00–21:30 输出（0.5h） 画图 / 录音 / 写 3 行日志

    弹性规则 - 只有 8 小时：砍掉当天实验的一半，不要砍算法和输出。 - 有 10 小时：多出的 1 小时给「补昨天没懂的」，别提前学新模块。 - 源码走读用计时器，2.5 小时到点就停，陷进一个大文件是最常见的时间黑洞。

    3. 实跑实验库（E1–E20）¶

    目标不是"跑通"，是用抓包/日志去印证源码里的函数。每个实验结束写一行：观察到什么 → 对应哪个类/函数。

    环境准备（今天 1–2 小时）¶

    # 方案 A：容器（推荐，已验证可跑）
docker run -d --name srs \
  -p 1935:1935 -p 1985:1985 -p 8080:8080 -p 8000:8000/udp \
  ossrs/srs:5

# 方案 B：本地二进制（不想用容器时）
brew install mediamtx
brew install --cask wireshark    # 或官网下载，确保 tshark 可用
python3 -m pip install --user aiortc   # 可选：可编程的 WebRTC 端
    • Docker Desktop 必须先启动；本机 4 核 / 约 2GB 内存，跑 SRS + 抓包够用，压测会吃紧。
    • 已实测：ossrs/srs:5 启动后 http://localhost:1985/api/v1/versions 返回 5.0.225，控制台 8080 返回 200。
    • SRS 的 rtc_server 默认开启（UDP 8000），可直接做 RTMP→WebRTC。
    • Chrome 已有，chrome://webrtc-internals 是最重要的观测面板。

    E1 首次通话观测（D1）¶

    • 做什么：Chrome 打开任意 WebRTC demo（或 mediamtx 的 WebRTC 页），开一次音视频通话。
    • 看什么：chrome://webrtc-internals 里的 outbound-rtp / inbound-rtp、码率、RTT、jitter、丢包。
    • 对应源码：api/ 里的 stats 结构；VideoReceiveStream2 的统计回调。

    E2 ffmpeg → SRS → Chrome（D2）¶

    # SRS 容器（见环境准备）
ffmpeg -re -stream_loop -1 -f lavfi -i testsrc2=size=1280x720:rate=30 \
  -c:v libx264 -preset ultrafast -tune zerolatency \
  -f flv rtmp://localhost:1935/live/livestream

# 浏览器打开 SRS 控制台自带的播放器：
#   http://localhost:8080/players/rtc_player.html?stream=livestream
# 或直接走 WHEP：http://localhost:1985/rtc/v1/whep/?app=live&stream=livestream
    - 看什么：SDP 里的 codec、payload type、a=rtpmap、ICE ufrag、a=setup。 - 对应源码：pc/sdp_offer_answer.cc 的 SDP 生成；media/engine 的 codec 协商。 - 备选：不想用容器就用 mediamtx（RTSP 8554 / WebRTC 8889），命令见附录。

    E3 tshark 抓 RTP（D3）¶

    sudo tshark -i en0 -f "udp port 8554" -Y rtp \
  -T fields -e rtp.seq -e rtp.timestamp -e rtp.ssrc -e rtp.marker | head -50
    - 看什么：seq 连续递增、timestamp 按 90000Hz 步进、marker 标记帧尾。 - 对应源码：modules/rtp_rtcp/source/rtp_sender_video.cc 的打包逻辑。

    E4 P2P 与 candidate（D4）¶

    • 做什么：Chrome 两个标签页互连（或用 aiortc 起一个端），看 SDP 里的 candidate。
    • 看什么：host / srflx / relay 各出现几个，优先级顺序。
    • 对应源码：p2p/base/p2p_transport_channel.cc、basic_ice_controller.cc。

    E5 码率与弱网（D5）¶

    • 做什么：通话中看 webrtc-internals 的 availableOutgoingBitrate 变化；用 Network Link Conditioner 或手机热点限速制造波动。
    • 看什么：码率下降时先降分辨率还是帧率？关键帧请求是否变多？
    • 对应源码：goog_cc/goog_cc_network_control.cc、video/adaptation/。

    E6 发送节奏（D6）¶

    sudo tshark -i en0 -Y "rtp" -T fields -e frame.time_delta -e rtp.seq | head -100
    - 看什么：包间隔是否均匀（pacing 生效），突发是否成簇（probe）。 - 对应源码：modules/pacing/pacing_controller.cc。

    E7 复盘（D7）¶

    • 把 W1 的图补齐：分层图、连接时序、RTP 头、GCC 环。

    E8 SDP 逐行分析（D8）¶

    • 做什么：保存一次 Offer/Answer，逐行标注：m-line、codec、a=setup、a=ice-ufrag、a=fingerprint、a=ssrc。
    • 对应源码：pc/sdp_offer_answer.cc、pc/jsep_transport_controller.cc。

    E9 TURN relay（D9）¶

    docker run -d --name coturn --network host coturn/coturn \
  -n --realm=example.org --user=test:test --lt-cred-mech \
  --listening-port=3478 --fingerprint
# Chrome 里把 iceTransportPolicy 设为 relay，或在 SRS 端只给 relay candidate
    - 看什么：SDP 出现 typ relay，RTT 变大，码率下降。 - 对应源码：p2p/base/turn_port.cc。

    E10 乱序/丢包注入（D10）¶

    方案 A（推荐，可控）：起一个 Linux 容器做 UDP 代理，用 tc netem 加丢包/延迟：

    docker run -it --rm --cap-add=NET_ADMIN --name netem ubuntu:22.04 bash
# 容器内：
apt update && apt install -y iproute2
tc qdisc add dev eth0 root netem loss 10% delay 100ms
    再把 WebRTC 的 UDP 端口指到这个容器转发（或用 socat 做端口映射）。

    方案 B（最省事）：macOS 安装 Xcode 的 Network Link Conditioner，选 3G/Lossy 预设。

    • 看什么：NACK 重传、卡顿、jitter buffer 增长、码率下降顺序。
    • 对应源码：api/video/frame_buffer.cc、modules/video_coding/nack_requester.cc。

    E11 AEC 录音对比（D11）¶

    • 做什么：开/关 AEC 各录一段（扬声器外放 + 麦克风），对比回声残留。
    • 对应源码：modules/audio_processing/aec3/echo_canceller3.cc。

    E12 Simulcast 观察（D12）¶

    • 做什么：SRS 支持 WebRTC 多流；或用 mediasoup demo 观察三层流。
    • 看什么：订阅端带宽变化时切到哪一层，是否请求关键帧。
    • 对应源码：modules/video_coding/svc/、video/adaptation/。

    E13 NACK/PLI（D13）¶

    • 做什么：E10 的弱网环境下，在 SRS 控制台或日志里看 RTCP 反馈。
    • 看什么：丢包后 NACK 频率、PLI 触发、关键帧变大。
    • 对应源码：rtp_video_stream_receiver2.cc 的 nack_module_、RequestKeyFrame。

    E14 网关/SFU 部署（D15）¶

    • 做什么：SRS 容器同时接 RTMP 和 WebRTC，多路推流、多路播放，观察转发关系。
    • 看什么：一路输入、多路订阅时 SRS 的 CPU 与带宽；WebRTC 播放的端到端延迟。
    • 对应源码：media/engine/webrtc_video_engine.cc。

    E15 录制 + 转推（D16）¶

    • 做什么：SRS 容器开 DVR 录制；ffmpeg 把流转推到另一个 RTMP 实例。
    • 看什么：录制文件的时间戳、转推延迟。
    • 对应源码：call/rtp_video_sender.cc、音频发送路径。

    E16 压测 + 监控（D17）¶

    • 做什么：ffmpeg 起 5–10 路推流，观察 mediamtx CPU/内存与丢包。
    • 看什么：瓶颈在解码、转发还是网络。
    • 对应源码：rtp_video_stream_receiver2 的收包路径。

    E17 RTSP 摄像头接入（D18）¶

    • 做什么：用 ffmpeg 模拟 RTSP 源（或真实摄像头），经 mediamtx 转 WebRTC。
    • 看什么：首帧时间、GOP 影响、时间戳对齐。
    • 对应源码：pc/ 的 SDP 协商、video/timing/。

    E18 弱网端到端（D19）¶

    • 做什么：30% 丢包 + 200ms 延迟下跑完整通话。
    • 看什么：卡顿率、码率、分辨率、音频是否优先保。
    • 对应源码：call/rtp_transport_controller_send.cc、modules/pacing。

    E19 设计演练（D20）¶

    • 做什么：白板画「百万设备接入 + 数十万并发观看」，标出瓶颈。
    • 对照：你的积加（百万设备）+ 好未来（数十万在线）经历。

    E20 总结（D21）¶

    • 做什么：把 7 张图 + 3 个项目卡片 + 弱网决策树串成 30 分钟讲解。

    附录：常用命令¶

    SRS（已验证端到端）¶

    # 启动（CANDIDATE 必须填宿主机 IP，否则 SDP 里是容器内网地址，浏览器连不上）
docker run -d --name srs \
  -e CANDIDATE=$(ipconfig getifaddr en0) \
  -p 1935:1935 -p 1985:1985 -p 8080:8080 -p 8000:8000/udp \
  ossrs/srs:5

# 健康检查
curl -s http://localhost:1985/api/v1/versions

# 推流
ffmpeg -re -f lavfi -i testsrc2=size=1280x720:rate=30 \
  -c:v libx264 -preset ultrafast -tune zerolatency \
  -f flv rtmp://localhost:1935/live/livestream

# 看流
curl -s http://localhost:1985/api/v1/streams/ | python3 -m json.tool

# 播放
# 控制台： http://localhost:8080/players/rtc_player.html?stream=livestream
# WHEP  ： http://localhost:1985/rtc/v1/whep/?app=live&stream=livestream

# 停止/删除
docker rm -f srs

    实测记录（2026-11-12）¶

    • 推流：ffmpeg → RTMP，H.264 1280×720 + AAC，SRS API 能查到流。
    • 播放：Headless Chrome 157 通过 WHEP 建立连接，connection=connected，解码 8 帧，1280×720 / 31fps，jitter 3ms，0 丢包。
    • SRS 日志：RTC: Subscriber url=/live/livestream established，spkts=(349, rtp:343)，rtcp=(pli:2)。
    • 关键点：Docker 里必须 -e CANDIDATE=<宿主机IP>，否则 SDP 给的是容器内网地址。
