    复习资料包（逐日可执行版）¶

    之前那份只有"资源清单"，没到能直接照做的程度。这份按 模块 → 资料 → 时长 → 输出 → 自检 拆开，一天对照一页就行。 原则：必读只占 20%，但覆盖 80% 的面试题；选读有空再看；标「跳过」的别碰。 与源码走读、实跑实验整合后的每日日程，见 打卡表-21天-复习+源码+实跑.md。

    0. 使用说明¶

    1. 先做诊断再读书：11/12 先做 30 题自测，会的模块直接看「自检问题」，答得上就跳过。
    2. 一份资料读三遍，不如一张图画三遍：每个模块的产出物是图或讲解录音，不是笔记摘抄。
    3. 官方源优先：RFC、标准、源码 > 书 > 中文博客。中文博客只用来建立直觉，不作为面试依据。
    4. 每天算法雷打不动 1.5 小时，其余时间按下面的表走。

    2. 分模块资料详解¶

    M1 音视频基础（2h）¶

    • 必读
    • 《音视频开发进阶指南》第 1 章（音视频基础）、第 2 章（编码原理）
    • 自测题 1–6
    • 选读：颜色空间（YUV/RGB）、HDR 基础
    • 跳过：傅里叶变换、人耳听觉模型的数学推导
    • 自检：PTS/DTS 区别？GOP 长短的取舍？YUV420 为什么省带宽？

    M2 H.264 / H.265（3h）¶

    • 必读
    • ITU-T H.264 白皮书：只读 NAL 单元、Slice、SPS/PPS、GOP 四节
    • 实践：ffprobe -show_frames -select_streams v test.mp4，标出 I/P/B 帧
    • 码控：CBR / VBR / ABR / CRF 的差异与适用场景
    • 选读：H.265 的 CTU、并行工具、相比 H.264 的码率收益
    • 跳过：变换/量化/熵编码的公式推导
    • 自检：为什么 B 帧需要重排？IDR 和 I 帧的区别？弱网为什么先降码率不降分辨率？

    M3 FFmpeg（3h）¶

    • 必读
    • 官方文档：ffmpeg.html、ffprobe.html
    • 架构：demuxer → decoder → filter → encoder → muxer
    • 命令实践：转码、切片（HLS）、推 RTMP、抽帧、看包
    • 选读：libavformat 的 demux 流程、libavcodec 的 avcodec_send_packet/receive_frame
    • 跳过：filter 图的高级用法
    • 输出：写一条转码命令，逐参数解释（-c:v libx264 -preset -crf -g -b:v）
    • 自检：-crf 和 -b:v 能同时用吗？硬编怎么接？

    M4 RTP / RTCP（4h）¶

    • 必读
    • RFC 3550 §5（RTP 数据）、§6（RTCP）
    • RFC 4585（NACK / PLI）
    • RFC 5104（FIR / TMMBR）
    • RFC 6184（H.264 over RTP，了解分片）
    • 选读：RFC 3711（SRTP）
    • 跳过：RTCP 的 SDES 细节
    • 输出：RTP 头字段图 + SR/RR 字段图
    • 自检：SSRC 冲突怎么办？NACK 和 PLI 的触发条件？多流如何用 SSRC 区分？

    M5 拥塞控制与弱网（6h）¶

    • 必读
    • GCC 论文：Carlucci et al., Analysis and Design of the Google Congestion Control for WebRTC, MMSys 2016（DBLP 记录）
    • TWCC draft
    • 源码：modules/congestion_controller/goog_cc/、modules/congestion_controller/rtp/transport_feedback_adapter.cc
    • 选读：中文导读（灏天文库 7.1），只用来建立直觉
    • 跳过：BBR / PCC 等非 WebRTC 算法
    • 输出：GCC 双控制器协同图 + 升降策略说明
    • 自检：延迟控制器怎么判断 overuse？TWCC 为什么把计算搬到发送端？FEC 和 NACK 的取舍？

    M6 WebRTC 连接建立（4h）¶

    • 必读
    • RFC 8445（ICE）、RFC 5764（DTLS-SRTP）、RFC 4566（SDP）
    • 《WebRTC 权威指南》信令与连接章节
    • 源码：pc/peer_connection、pc/sdp_offer_answer、p2p/base/
    • 选读：Trickle ICE、Bundle、RTCP-mux
    • 跳过：TURN 服务器部署细节
    • 输出：Offer/Answer → ICE → DTLS → SRTP 时序图
    • 自检：a=setup:actpass 的作用？host/srflx/relay 三种 candidate 何时用？

    M7 jitter buffer / NetEQ（4h）¶

    • 必读
    • 源码：api/video/frame_buffer.cc、video/timing/、modules/audio_coding/neteq/
    • 概念：抖动缓冲、丢包隐藏（PLC）、变速播放、音画同步
    • 选读：NetEQ 的自适应算法论文/博客
    • 跳过：NetEQ 的定点运算优化
    • 输出：jitter buffer 状态机 + PLC 处理流程图
    • 自检：buffer 太大/太小分别什么后果？PLC 和 FEC 的区别？

    M8 音频 3A（6h）¶

    • 必读
    • 源码：modules/audio_processing/aec3/、ns/、agc/、vad/
    • 原理：回声路径、自适应滤波、双讲检测、谱减、目标增益
    • 选读：深度学习降噪（RNNoise 等）
    • 跳过：波束成形（除非面会议硬件）
    • 输出：回声产生与消除链路图 + 双讲处理说明
    • 自检：AEC 双讲为什么难？ANS 谱减的副作用？AGC 增益怎么定？

    M9 Simulcast / SVC / SFU（4h）¶

    • 必读
    • mediasoup 文档：Simulcast、SVC、Consumer 优选
    • 关键帧《音视频 WebRTC 面试题 53 期》（链接）
    • 选读：VP9 SVC、AV1 SVC 现状
    • 跳过：MCU 的混流算法细节
    • 输出：Simulcast vs SVC 对比表（带宽、兼容性、切换体验）
    • 自检：SFU 切流为什么要请求关键帧？SVC 丢层为什么不用重连？

    M10 媒体服务 / 录制 / 转推（4h）¶

    • 必读
    • mediasoup 架构、SRS Wiki、Janus 文档（任选两个读架构）
    • 声网 / 即构 / 火山引擎 RTC 技术博客（选 3 篇）
    • 选读：级联与边缘节点
    • 跳过：具体厂商 SDK 接入
    • 输出：SFU 集群 + 级联架构图；录制链路图（单流/合流）
    • 自检：RTP 转 RTMP 的坑？合流录制的成本在哪？

    M11 大规模 + 云原生（4h）¶

    • 必读
    • K8s 核心概念：Deployment / Service / HPA / ConfigMap
    • QoE 指标：首帧、卡顿率、端到端延迟、加入成功率
    • 选读：Prometheus + Grafana 基础
    • 跳过：Service Mesh、Operator 开发
    • 输出：10 万并发 RTC 架构图（接入/调度/媒体/存储/监控）
    • 自检：媒体服务上 K8s 的坑？如何做容量规划？

    M12 设备协议（4h）¶

    • 必读
    • GB/T 28181-2022 全文（PDF）：重点 信令流程、SIP 方法、RTP 传输
    • ONVIF Profiles（S/G/T 差异）
    • RFC 2326（RTSP）
    • 选读：海康/大华私有协议文档
    • 跳过：SIP 协议全量
    • 输出：GB28181 注册/点播/注销时序图
    • 自检：GB28181 和 RTSP 的本质差异？128 路 NVR 怎么调度？

    M13 端侧（3h）¶

    • 必读
    • Android MediaCodec 文档（若投端侧岗）
    • 硬编 vs 软编的取舍、码控、关键帧
    • 复盘积加项目：4 类机型、君正/瑞芯微/安凯差异、4G 弱网
    • 选读：渲染管线（Surface/Texture）、功耗优化
    • 跳过：iOS 细节（除非投 iOS 岗）
    • 输出：端侧采集→编码→推流管线图 + 功耗/带宽优化点
    • 自检：首帧怎么优化？低功耗相机怎么省电省流量？

    M14 系统设计（6h）¶

    • 必读：7 题提纲（见《复习计划》第 7 节），每题一页纸
    • 选读：《设计数据密集型应用》第 1、5、6 章
    • 跳过：分布式事务、共识算法
    • 输出：7 页设计稿，每页含「需求 → 架构 → 瓶颈 → 取舍」
    • 自检：10 万并发 RTC 的瓶颈在哪一层？怎么扩容？

    M15 算法（每天 1.5h，累计 26h）¶

    • 必读：LeetCode 热题 100，按周分配：
    • 第 1 周：数组/字符串/链表/栈队列/哈希（前 50）
    • 第 2 周：二叉树/DFS/BFS/回溯（中 30）
    • 第 3 周：DP/堆/贪心（后 20）
    • 手写题 6 个：线程池、无锁队列、LRU、生产者消费者、单例、智能指针
    • 输出：60 题 + 6 个手写
    • 自检：中等题 25 分钟内 bug-free

    M16 C++ 八股（4h）¶

    • 必读
    • 虚函数/虚表、智能指针与循环引用、移动语义、内存序
    • 多线程：锁、条件变量、原子操作、无锁队列
    • 《Effective C++》选读 10 条
    • 选读：C++17 新特性
    • 跳过：模板元编程
    • 输出：手写线程池 + 无锁队列
    • 自检：shared_ptr 线程安全吗？内存序有哪几种？
